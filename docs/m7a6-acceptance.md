# M7A.6 — Native form files replace the custom format

Updated 2026-11-08. Status: **COMPLETE**, under
[ADR 0099](decisions/0099-native-only-form-workflows.md).
This gate removes the custom format; it does not extend the common runtime or P9.

The shipped codec/module, public `import_form`/`export_form` APIs, source import
branches, form Save/Export/remove-export fallbacks, browser/Word file filters and
custom example are removed. There is no retained importer, compatibility mode,
converter or renamed custom format. The shared Rust designer/runtime stays in
place behind native `.frm`/`.frx` workflows. A repository check rejects retired
format references in product Rust, the codec file and custom example extension.
Historical ADRs and M2 evidence remain explicitly superseded for format support.

Insert UserForm attaches an inert native template, using the existing dimensions
and code page 1252 of the current shell import profile. New forms remain modified
until acknowledged after native file IO. Save/Export and export-before-remove
use the revision-bound native snapshot request. Renamed components export their
current name in the frame, filename and source attribute. Fixed embedded-project
component identities still refuse insertion/rename during package-copy export.
Unsupported code-page characters, resource edits and selection-group persistence
refuse explicitly; runtime values never replace authored designer state.

The original CustomerForm demonstration is now a native pair generated by
`crates/vba-ide/examples/customer_form.rs` from authored VBA and designer edits.
Its files contain no Office-created binaries or vendor artwork. Native/browser
captures use that pair. The browser test imports it inertly, clicks Submit,
stops/continues the real handler, verifies output 7, exports both native files,
checks exact authored source and binary resource identity, and reimports without
execution. The reopened designer was inspected.

Useful archive-era tests are retained with native transport: exact source,
layout/tab order, malformed companion rejection before mutation, stale save
receipts, rename/export/remove and native file failure behavior. Group editing
remains tested in memory; native export refuses unsupported group persistence.
New forms also use the existing native pre-execution refusal for fields that
collide with built-in BackColor/ForeColor properties. Two GUI tests use the
existing native eight-frame settling allowance; callback, debugger and keyboard
assertions remain unchanged. No VM, host-permission, memory or execution limit
was raised.

Shared CI/strict Clippy, WASM/WASI/UI/Xvfb-native and both pinned-host gates pass;
results and exact repository revisions are recorded in
[implementation progress](implementation-progress.md). The complete 15-flow
browser suite passes, including the migrated demo and M7A.5 native save/reopen.
Both hosts' useful callback tests now use native form files; Word's source-picker
and dropped-file routes no longer advertise/route the removed format as VBA.

[M7A.5](m7a5-acceptance.md) file/save/signature/receipt rules remain intact:
ordinary document Save preserves original VBA bytes, edited package copy export
retains the original editor's modified state, and browser downloads never imply
a disk-save acknowledgment. M7A.7 combined acceptance remains next. M8.5 fresh
Excel/Word comparisons remain NOT_RUN; uncommon compatibility remains in P9.
